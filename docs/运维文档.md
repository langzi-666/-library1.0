# 图书管理系统运维文档

## 1. 运维概述

### 1.1 文档目的
本文档旨在为系统运维人员提供系统日常运维、监控、故障处理等方面的指导。

### 1.2 系统架构
- **前端**：Vue 3 + Nginx
- **后端**：Spring Boot 2.7.18 + 内嵌Tomcat
- **数据库**：MySQL 8.0+
- **监控**：Druid监控、系统监控

### 1.3 运维职责
- 系统监控和维护
- 数据备份和恢复
- 故障处理和应急响应
- 性能优化和容量规划
- 安全管理和日志审计

## 2. 日常运维

### 2.1 系统监控

#### 2.1.1 应用监控

```bash

ps aux | grep java

# 检查应用端口

# 检查系统服务状态
systemctl status library-backend
```

**查看应用日志**
```bash

tail -f /opt/library-management/logs/backend.log

# 查看错误日志
grep ERROR /opt/library-management/logs/backend.log

# 查看最近100行日志
tail -n 100 /opt/library-management/logs/backend.log
```

#### 2.1.2 数据库监控

**检查数据库状态**

## 3. 数据备份

### 3.1 数据库备份

#### 3.1.1 自动备份脚本

```bash
#!/bin/bash
# 数据库自动备份脚本
# 文件位置：/opt/library-management/backup/backup-db.sh

BACKUP_DIR="/opt/library-management/backup"
DATE=$(date +%Y%m%d_%H%M%S)
BACKUP_FILE="$BACKUP_DIR/library_db_$DATE.sql"
DB_USER="library_user"
DB_PASS="your_password"
DB_NAME="library1.4"

# 创建备份目录
mkdir -p $BACKUP_DIR

# 备份数据库
mysqldump -u $DB_USER -p$DB_PASS $DB_NAME > $BACKUP_FILE

# 压缩备份文件
gzip $BACKUP_FILE

# 删除30天前的备份
find $BACKUP_DIR -name "library_db_*.sql.gz" -mtime +30 -delete

# 记录备份日志
echo "$(date '+%Y-%m-%d %H:%M:%S') - 数据库备份完成: $BACKUP_FILE.gz" >> $BACKUP_DIR/backup.log
```

#### 3.1.2 配置定时备份

```bash
# 编辑crontab
crontab -e

# 添加定时任务（每天凌晨2点备份）
0 2 * * * /opt/library-management/backup/backup-db.sh

# 查看定时任务
crontab -l
```

#### 3.1.3 备份验证

```bash
# 验证备份文件
gunzip -t library_db_20241201_020000.sql.gz

# 测试恢复（在测试环境）
mysql -u root -p test_db < library_db_20241201_020000.sql
```

### 3.2 应用备份

#### 3.2.1 应用文件备份

```bash
#!/bin/bash
# 应用文件备份脚本
# 文件位置：/opt/library-management/backup/backup-app.sh

BACKUP_DIR="/opt/library-management/backup"
DATE=$(date +%Y%m%d_%H%M%S)
BACKUP_FILE="$BACKUP_DIR/library_app_$DATE.tar.gz"

# 备份应用和配置
tar -czf $BACKUP_FILE \
    /opt/library-management/backend \
    /opt/library-management/frontend \
    /opt/library-management/logs \
    --exclude='*.log' \
    --exclude='target/*'

# 删除30天前的备份
find $BACKUP_DIR -name "library_app_*.tar.gz" -mtime +30 -delete

# 记录备份日志
echo "$(date '+%Y-%m-%d %H:%M:%S') - 应用备份完成: $BACKUP_FILE" >> $BACKUP_DIR/backup.log
```

### 3.3 备份策略

#### 3.3.1 备份频率
- **数据库备份**：每天1次（凌晨2点）
- **应用备份**：每周1次（周日凌晨3点）
- **完整备份**：每月1次（月初）

#### 3.3.2 备份保留
- **日常备份**：保留30天
- **周备份**：保留3个月
- **月备份**：保留1年

#### 3.3.3 备份验证
- 每周验证1次备份文件完整性
- 每月在测试环境测试恢复1次

```bash
systemctl start library-backend
```

#### 4.1.2 部分恢复

```bash

mysql -u library_user -p library1.4 < restore_data.sql
```

```bash
# 停止应用
systemctl stop library-backend

# 恢复应用文件
tar -xzf library_app_20241201_030000.tar.gz -C /

# 启动应用
systemctl start library-backend
```

## 5. 故障处理

### 5.1 应用故障

#### 5.1.1 应用无法启动

**检查步骤：**
1. 检查日志文件
   ```bash
   tail -f /opt/library-management/logs/backend.log
   ```

2. 检查端口占用
   ```bash
   netstat -tlnp | grep 8080
   ```

3. 检查Java进程
   ```bash
   ps aux | grep java
   ```

4. 检查配置文件
   ```bash
   cat /opt/library-management/backend/application-prod.yml
   ```

**常见问题：**
- 端口被占用：修改配置文件或停止占用端口的进程
- 内存不足：增加JVM内存参数或释放内存
- 配置文件错误：检查配置文件语法

#### 5.1.2 应用响应慢

**检查步骤：**
1. 检查系统资源
   ```bash
   top
   free -h
   ```

2. 检查数据库连接
   ```bash
   mysql -u root -p -e "SHOW PROCESSLIST;"
   ```

3. 检查慢查询
   ```bash
   tail -f /var/log/mysql/slow-query.log
   ```

4. 检查Druid监控
   - 访问Druid监控页面
   - 查看SQL监控和连接池监控

**优化措施：**
- 优化慢查询SQL
- 增加连接池大小
- 增加JVM内存
- 优化数据库索引

#### 5.1.3 应用崩溃

**处理步骤：**
1. 查看崩溃日志
   ```bash
   tail -n 500 /opt/library-management/logs/backend.log
   ```

2. 检查系统日志
   ```bash
   journalctl -u library-backend -n 100
   ```

3. 重启应用
   ```bash
   systemctl restart library-backend
   ```

4. 如果持续崩溃，检查：
   - 内存是否充足
   - 磁盘空间是否充足
   - 数据库连接是否正常

### 5.2 数据库故障

#### 5.2.1 数据库无法连接

**检查步骤：**
1. 检查MySQL服务
   ```bash
   systemctl status mysql
   ```

2. 检查MySQL日志
   ```bash
   tail -f /var/log/mysql/error.log
   ```

3. 检查网络连接
   ```bash
   telnet localhost 3306
   ```

4. 检查防火墙
   ```bash
   firewall-cmd --list-all
   ```

**常见问题：**
- MySQL服务未启动：启动MySQL服务
- 端口被占用：检查端口占用情况
- 连接数过多：检查连接数限制

#### 5.2.2 数据库性能问题

**检查步骤：**
1. 检查慢查询
   ```bash
   mysql -u root -p -e "SELECT * FROM mysql.slow_log ORDER BY start_time DESC LIMIT 10;"
   ```

2. 检查表大小
   ```sql
   SELECT 
       table_name,
       ROUND(((data_length + index_length) / 1024 / 1024), 2) AS size_mb
   FROM information_schema.TABLES
   WHERE table_schema = 'library1.4'
   ORDER BY size_mb DESC;
   ```

3. 检查索引使用情况
   ```sql
   SHOW INDEX FROM book;
   ```

**优化措施：**
- 优化慢查询SQL
- 添加缺失的索引
- 分析表统计信息
- 优化表结构

### 5.3 系统资源故障

#### 5.3.1 磁盘空间不足

**检查步骤：**
```bash
# 检查磁盘使用情况
df -h

# 查找大文件
find /opt/library-management -type f -size +100M

# 查找大目录
du -sh /opt/library-management/* | sort -h
```

**处理措施：**
- 清理日志文件
- 清理临时文件
- 清理旧备份文件
- 扩展磁盘空间

#### 5.3.2 内存不足

**检查步骤：**
```bash
# 检查内存使用情况
free -h

# 检查进程内存使用
ps aux --sort=-%mem | head -n 10
```

**处理措施：**
- 优化应用内存配置
- 增加系统内存
- 优化数据库缓存
- 重启服务释放内存

## 6. 性能优化

### 6.1 数据库优化

#### 6.1.1 定期优化

```bash
# 执行性能优化脚本
mysql -u root -p library1.4 < database/performance_optimization.sql

# 分析表
mysql -u root -p library1.4 -e "ANALYZE TABLE user, book, category, borrow_record;"

# 优化表
mysql -u root -p library1.4 -e "OPTIMIZE TABLE user, book, category, borrow_record;"
```

#### 6.1.2 慢查询优化

```sql
-- 查看慢查询
SELECT * FROM mysql.slow_log ORDER BY start_time DESC LIMIT 10;

-- 分析慢查询
EXPLAIN SELECT * FROM book WHERE title LIKE '%关键词%';

-- 优化索引
CREATE INDEX idx_title ON book(title);
```

### 6.2 应用优化

#### 6.2.1 JVM参数优化

编辑启动脚本，调整JVM参数：
```bash
java -jar \
  -Xms1024m \
  -Xmx2048m \
  -XX:+UseG1GC \
  -XX:MaxGCPauseMillis=200 \
  -XX:+HeapDumpOnOutOfMemoryError \
  -XX:HeapDumpPath=/opt/library-management/logs/heapdump.hprof \
  library-management-system-1.0.0.jar
```

#### 6.2.2 连接池优化

编辑 `application-prod.yml`：
```yaml
spring:
  datasource:
    druid:
      initial-size: 10
      min-idle: 10
      max-active: 50
      max-wait: 60000
```

## 7. 日志管理

### 7.1 日志文件

#### 7.1.1 日志位置
- **应用日志**：`/opt/library-management/logs/backend.log`
- **MySQL错误日志**：`/var/log/mysql/error.log`
- **MySQL慢查询日志**：`/var/log/mysql/slow-query.log`
- **Nginx访问日志**：`/var/log/nginx/library-access.log`
- **Nginx错误日志**：`/var/log/nginx/library-error.log`

#### 7.1.2 日志轮转

配置logrotate：
```bash
# 创建logrotate配置
cat > /etc/logrotate.d/library << 'EOF'
/opt/library-management/logs/*.log {
    daily
    rotate 30
    compress
    delaycompress
    missingok
    notifempty
    create 0644 library library
    sharedscripts
    postrotate
        systemctl reload library-backend > /dev/null 2>&1 || true
    endscript
}
EOF
```

### 7.2 日志分析

#### 7.2.1 错误日志分析

```bash
# 统计错误数量
grep ERROR /opt/library-management/logs/backend.log | wc -l

# 查看最常见的错误
grep ERROR /opt/library-management/logs/backend.log | sort | uniq -c | sort -rn | head -n 10

# 查看最近1小时内的错误
grep ERROR /opt/library-management/logs/backend.log | grep "$(date -d '1 hour ago' '+%Y-%m-%d %H')"
```

#### 7.2.2 访问日志分析

```bash
# 统计访问量
wc -l /var/log/nginx/library-access.log

# 统计IP访问量
awk '{print $1}' /var/log/nginx/library-access.log | sort | uniq -c | sort -rn | head -n 10

# 统计最受欢迎的页面
awk '{print $7}' /var/log/nginx/library-access.log | sort | uniq -c | sort -rn | head -n 10
```

## 8. 安全管理

### 8.1 安全加固

#### 8.1.1 系统安全

```bash
# 定期更新系统
yum update -y
# 或
apt-get update && apt-get upgrade -y

# 配置防火墙
firewall-cmd --permanent --add-service=http
firewall-cmd --permanent --add-service=https
firewall-cmd --reload

# 禁用不必要的服务
systemctl disable unused-service
```

#### 8.1.2 数据库安全

```sql
-- 创建专用数据库用户
CREATE USER 'library_user'@'localhost' IDENTIFIED BY 'strong_password';
GRANT ALL PRIVILEGES ON library1.4.* TO 'library_user'@'localhost';
FLUSH PRIVILEGES;

-- 定期更换密码
ALTER USER 'library_user'@'localhost' IDENTIFIED BY 'new_strong_password';
```

#### 8.1.3 应用安全

- 定期更新依赖包
- 检查安全漏洞
- 配置HTTPS
- 限制Druid监控访问（IP白名单）

### 8.2 安全审计

#### 8.2.1 日志审计

```bash
# 检查异常登录
grep "登录失败" /opt/library-management/logs/backend.log
```
